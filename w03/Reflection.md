# Week 03 — Reflection

## 1. My Learning Experience

This week focused on exploring AI assistants, improving technical questions, and investigating an open-source VLSI tool. I learned that AI can help simplify unfamiliar topics, but understanding a concept requires more than reading a generated explanation.

I also explored how providing background information and specific requirements can make a prompt more useful. These skills can support my continued Python learning and my long-term goal of developing stronger knowledge of VLSI physical design.

## 2. What I Learned About AI Tools

Different AI platforms can assist with explanations, programming, research, and document-based learning. Choosing an appropriate tool depends on the problem I want to solve.

One important lesson is that a detailed answer is not necessarily a correct answer. Technical information should be checked against reliable sources, particularly when it involves software commands, engineering workflows, or implementation details.

I also learned that comparing responses can help identify differences in clarity and completeness. However, agreement between two AI tools does not automatically establish that a claim is true.

## 3. Improving My Prompting Skills

I learned that a useful prompt should explain what I need, provide relevant context, and specify the expected response.

For example, instead of asking a general question about a VLSI tool, I can request its purpose, input files, output files, and role in the physical-design process.

This approach can help me obtain explanations that are more relevant to my current level of understanding.

## 4. Open-Source VLSI Tool Investigation

My selected tool for this activity is OpenROAD because it is relevant to digital ASIC physical design.

The investigation helped me organise my understanding of the implementation flow, including floorplanning, placement, clock-tree synthesis, routing, and timing-related checks.

I also explored the importance of input files such as gate-level netlists, Liberty libraries, LEF files, and timing constraints. Understanding how these files contribute to implementation is important when preparing a design for an open-source physical-design flow.

A possible area for future exploration is the use of machine learning to estimate congestion, predict timing problems, or help investigate implementation parameters.

## 5. Challenges and Areas for Improvement

Some engineering concepts require further study, especially the relationships between technology files, timing constraints, and physical-design results.

I also need more practical experience interpreting tool reports and understanding how implementation changes affect power, performance, and area.

My next step is to continue learning Python, review official tool documentation, and practise with small designs that I can run and analyse in my own environment.

## 6. Questions for the ML Masterclass

1. How do machine learning algorithms update their parameters during training, and how can I understand this process through a simple Python example?

2. How can machine learning be applied to VLSI physical design to help predict timing violations or routing congestion, and how should these predictions be evaluated against actual tool results?

## 7. Final Reflection

This week's activities helped me recognise that effective AI-assisted learning involves asking focused questions, checking important information, and explaining concepts independently.

I want to use AI as a supporting resource while continuing to build the practical skills needed to understand engineering tools and their results. My main goal is to connect machine learning fundamentals with real VLSI problems through experimentation and verification.

**My learning principle:** Ask clearly, verify carefully, practise independently, and understand the result.
